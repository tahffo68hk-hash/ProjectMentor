# 抖音主页到豆包分析器设计说明

## 目标

输入一个抖音博主主页链接，自动滚动并读取该页面可访问范围内的全部公开视频链接，建立分析队列，并逐条交给豆包网页版生成口播与文案整理结果。结果保存为本地 Markdown。

## 范围与边界

- 只读取浏览器中可见、公开且用户有权处理的内容。
- 不调用或破解抖音隐藏接口，不绕过登录、验证码、频率限制或访问控制。
- 未登录时只处理页面已展示的作品；页面提示登录后查看更多时暂停并提示用户。
- 豆包使用用户已登录的网页版会话，工具不读取或保存密码、Cookie、Token。

## 方案

本地桌面页面负责任务管理，浏览器自动化负责两个网站的可见 UI 操作：

1. 打开抖音主页，检查账号信息、作品列表和登录状态。
2. 从可见作品卡片读取标题、视频链接和顺序。
3. 持续滚动页面，直到页面到底、作品数量达到主页显示值，或出现登录/验证码阻塞。
4. 去重后逐条打开/提交给豆包，并使用固定提示词请求：标题、口播全文、字幕/画面文案、结构摘要和不确定项。
5. 等待豆包回复，从可见回复区域读取结果，写入 Markdown；失败任务记录原因并允许重试。

## 组件

- `collector`：主页导航、滚动、卡片识别、链接去重。
- `queue`：任务状态、顺序、重试次数和断点信息。
- `doubao_adapter`：豆包会话检查、提示词提交、回复读取。
- `exporter`：安全文件名、Markdown 文件和汇总 CSV。
- `ui`：主页链接输入、数量限制、开始/暂停、进度和错误提示。
- `checkpoint`：实时保存已发现链接和已完成状态，支持中断后继续，不因单条失败丢失队列。

## 数据流与状态

任务状态为 `pending -> collecting -> analyzing -> succeeded`，异常进入 `failed`，用户重试后回到 `pending`。每条记录至少包含原始链接、标题、发现顺序、状态、错误信息、创建时间和输出路径。

## 错误处理

- 页面要求登录：保留已收集链接，暂停并提示用户在浏览器中登录。
- 出现验证码或安全拦截：停止自动操作，等待用户手动处理，不尝试绕过。
- 豆包页面元素变化或回复超时：标记失败，保存原始链接和错误，支持单条重试。
- 输出文件重名：使用序号和视频 ID，避免覆盖已有结果。

## 验证标准

- 给定已验证的主页链接，能识别博主名和作品数量。
- 能收集前 10 条可见视频链接且无重复。
- 能持续收集页面可访问范围内的全部视频链接且无重复，并在页面到底或访问受限时给出明确提示。
- 每条任务都能显示明确状态。
- 豆包成功回复能保存为可读 Markdown，失败不会丢失队列。
- 不触碰密码、Cookie、隐藏接口或验证码绕过逻辑。

## 后续扩展

验证版稳定后，再增加全部公开作品、断点续跑、按日期筛选、CSV/Excel 汇总和人工审核后再分析等功能。
